# 扩展示例教学数据

用于本地体验、截图及功能演示，**全部为虚构教学记录**。人名采用常见中文姓名，不代表真实学员；新增联系方式留空。练习图由项目脚本绘制，是教学示意图，不是真实学生作品。

导入工具位于 `scripts/demo-data/seed.py`，不随 Spring Boot 启动运行。已有基础演示库中通常有 3 名学员；扩充后有 58 名学员、5 名教师、7 个常规班及按科目组织的补课班。实际课次数量取决于导入日期和已有排课，脚本遇到教师、班级或教室时间冲突时会保留原课次。

包含连续数周的课表、历史考勤、待审批请假、完成或待上课的补课、一例转班、教学任务、56 份作品、63 个作品版本、具体点评、教学资源、通知及反馈。不是每项任务都已交齐，也不是每份作品都已点评。

## 准备

先按 README 启动后端与基础演示数据库。使用 Python 3.10 及以上版本，安装独立工具依赖：

```powershell
python -m pip install -r scripts/demo-data/requirements.txt
```

本工具用于扩充自带演示库，按名称查找“素描启蒙 A 班”和“周末水彩班”，不假设数据库主键。若已手动大幅扩充这两个班，工具会停止，需按自己的库调整脚本。不要将它作为通用生产数据迁移工具。

## 预览：不提交数据库，不上传文件

在项目根目录设置专用环境变量。以下密码需要自行填写，不要将配置文件或终端记录提交到 GitHub。

```powershell
$env:DEMO_DB_HOST = '127.0.0.1'
$env:DEMO_DB_PORT = '3306'
$env:DEMO_DB_NAME = 'studio'
$env:DEMO_DB_USER = 'studio'
$env:DEMO_DB_PASSWORD = '填写本地数据库密码'
$env:PYTHONIOENCODING = 'utf-8'
python scripts/demo-data/seed.py
```

默认使用当前日期推算教学周。可通过 `--date 2026-11-19` 固定基准日期。预览会在事务内生成数据、校验，再回滚；MySQL 自增序号可能因此产生正常的空号。预览摘要保存在忽略提交的 `work/demo-data/preview.json`。

## 正式导入演示库

先备份目标数据库。正式执行仍在一个业务事务内完成，文件通过后端上传接口保存，使用后端已配置的本地存储或 OSS，不需要把 OSS 密钥交给脚本。

```powershell
$env:DEMO_API_USERNAME = 'admin'
$env:DEMO_API_PASSWORD = '填写该库管理员密码'
$env:DEMO_API_URL = 'http://127.0.0.1:18080/api'
python scripts/demo-data/seed.py --apply
```

生产子路径部署的 API 地址应包含子路径，例如 `https://你的域名/art-studio/api`。必须确保数据库配置与 API 指向同一个环境。将不同环境的 `--output` 指定为不同目录，避免混淆上传清单。

导入过程：

- 获取与业务写入共用的排课事务锁，阻止同时修改课表。
- 只修改与原始种子姓名完全一致的少量姓名及其账户显示名；账号、密码、头像保持不变。原始学员占位手机号会清空，其他联系方式不动。
- 保留已有业务数据，新增的报名与课次按照生效日期匹配；转班前后分别属于原班和目标班。
- 检查教师、教室、班级和学员时间冲突、课次容量、有效报名、未来考勤、补课链及作品提交时间。校验失败会回滚本次业务事务。
- 用审计记录 `DEMO_DATA_IMPORT / realistic-teaching-v1` 标识导入批次；重复执行直接返回 `already_imported`，不会叠加同一批数据。

导入摘要及主键清单保存在 `work/demo-data/applied.json`，上传文件清单保存在同目录的 `uploaded-files.json`。这些运行资料和数据库备份均不提交到仓库。

文件上传使用独立的 HTTP 请求，不能参与 MySQL 业务事务。如果在上传后因网络或校验失败而回滚，部分文件可能已经保存；请按 `uploaded-files.json` 核对后清理未被引用的文件，不要直接反复重跑或清空整个 Bucket。恢复整个数据库备份会覆盖备份之后的新业务记录，恢复前需停写并核对。

## 文件和时间

上传文件名采用 `practice-001-v1.png`、`practice-001-v2.png` 和 `reference-01-v2.png`。对象键继续由后端生成，遵守 `studio/works/年/月/上传用户ID/随机ID.png` 与 `studio/resources/...` 的目录规范，OSS 文件保持私有读。

为了呈现连续的历史教学过程，模拟作品、版本、点评和文件元数据使用对应的历史日期；实际 OSS 对象上传时间为执行脚本的时间。数据是导入时的静态快照，后续日历推进不会自动更新模拟考勤。

新增教师仅建立教师档案，不自动开通登录账户。需要体验这些教师的角色时，应由管理员按正常流程创建并绑定账户。

## 原创作品与版本升级

`artwork_svg.py` 按素描静物、结构素描、水彩植物、少儿创意、墨竹和油画风景六类绘制原创 SVG，输出 1400 × 1050 PNG。PNG 用于应用展示，旁边的 SVG 保留可编辑源文件。相同种子维持主体构图，版本间逐步调整明暗、色彩、叶组、辅助线及细节。它们是模拟课堂习作，不是真实学生作品或外部作品照片。

只生成样图，不连接数据库：

```powershell
python scripts/demo-data/artwork_svg.py --output work/artwork-preview
```

对已导入 `realistic-teaching-v1` 的演示库可执行专用升级。先沿用上文环境变量，备份目标数据库，然后先预览：

```powershell
python scripts/demo-data/upgrade_artwork.py --output work/artwork-upgrade
# 确认 plan.json、SVG/PNG 和数据库备份后执行
python scripts/demo-data/upgrade_artwork.py --apply --output work/artwork-upgrade
```

该升级只按原导入批次记录定位 56 份虚构作品和 7 份资源，替换展示文件并完善修改说明、点评。49 份已有点评的作品各补充一个修改版本，最终为 112 个版本、105 条点评；7 份尚无点评的作品继续保持待点评状态。文件通过应用上传接口保存，遵循 `studio/works/年/月/用户ID/随机ID.png` 或 `studio/resources/...` 的目录和私有权限，不向脚本提供 OSS 密钥。

升级前后版本号连续，提交时间不超过任务截止日，点评晚于对应提交；同一作品的多个版本保留同一构图。新图片与旧图片使用不同的对象键，旧文件不删除。脚本通过 `DEMO_ARTWORK_UPGRADE / teaching-artwork-svg-v2` 防止重复追加，检测到原演示文件被手动修改或业务数据在准备期间变化时会停止。上传清单记录 SHA-256；失败后用同一目录重试可复用已上传文件。没有原导入批次的库不能直接运行此升级。

作品列表显示缩略图，详情保留完整版本记录，并支持选择“修改前后对比”。管理员、教师、学员和监护人继续使用原数据权限；对比页面不扩大文件的访问范围。
