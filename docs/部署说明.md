# Linux 生产部署

本模板不包含任何现有服务器配置。以下以 Java 17、MySQL 8、Nginx 和 systemd 为例，替换域名、数据库账号及目录后使用。前端公开路径为 `/art-studio/`，后端仅监听本机 18080。

## 构建

```bash
mvn -f backend/pom.xml clean package
cd frontend
npm ci
npm run build
```

将 JAR 放到 `/opt/art-studio/studio.jar`，将 frontend/dist 内的文件放到 `/opt/art-studio/web/`。创建专用的非 root 系统用户 `studio`，将 `/opt/art-studio/uploads` 设为该用户可写；源码、JAR、静态页面不需要应用写权限。

## 数据库

先由管理账号创建独立数据库 studio，执行 database/init.sql 建表，再创建应用账号，仅授予该库 SELECT、INSERT、UPDATE、DELETE。prod 不自动建表、不创建演示数据；不要导入开发或生产数据备份作为公开演示素材。

database/migrations 是旧版本库的增量脚本，新库已包含最终表结构，无需重复执行。示例：

```bash
mysql -h 127.0.0.1 -u DATABASE_ADMIN -p studio < database/init.sql
```

## 配置和启动

复制 deploy/production.env.example 为 `/opt/art-studio/.env`，填写数据库密码、全新随机 JWT_SECRET，以及首次管理员密码 STUDIO_BOOTSTRAP_ADMIN_PASSWORD（至少 12 字符、最多 72 UTF-8 字节）。环境文件由 root 保管并设为 600，systemd 读取后传给进程。首次空库启动创建 admin，成功后可从配置中删除首次密码并重启；已有账号时不会覆盖账号。

复制 deploy/studio.service 到 `/etc/systemd/system/studio.service`，核对 Java 路径、用户和目录，然后执行：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now studio
sudo systemctl status studio
```

## Nginx 和 HTTPS

deploy/nginx.conf 是 HTTP 初始模板，使用自己的域名和证书配置 HTTPS 后再用于公网登录。请把模板中的 example.com 换成自己的域名，合并到自己的站点配置，避免覆盖其他服务；执行 `nginx -t` 成功再 reload。

静态资源位于 `/art-studio/`，接口 `/art-studio/api/` 在 Nginx 去除公开前缀后转发到后端 `/api/`。不要对外开放 18080，也不要把 Vite 开发服务直接放到公网。SERVER_FORWARD_HEADERS_STRATEGY=framework 只适用于后端被可信反向代理隔离的部署方式。

## 更新与备份

备份数据库、uploads 和服务器私有环境配置。使用 OSS 时，还需独立保留云端对象；本地文件不会因为启用 OSS 而自动迁移。恢复时数据库文件记录与实际对象应一致。变更前备份 Nginx 配置和旧 JAR，升级后检查健康接口、登录、首页、深层页面刷新和文件读取。

切换到根目录部署时应重新构建并同步修改 Nginx、API 与 SPA 回退位置，不能只修改一个前端路径。
